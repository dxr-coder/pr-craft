# Git 基础

## 一句话理解 Git

**Git = 代码的"存档系统"**

每次你完成一小段工作，就"存档"一次。之后随时可以读档。

## 为什么要用 Git？

- 改坏了能回退
- 记录每次改了啥
- 和 GitHub 配合，备份 + 协作

## 核心工作流程

```
工作区         暂存区         本地仓库         远程仓库
(你的文件) → add → (待提交) → commit → (已存档) → push → (GitHub)
                                                      ← pull ←
```

## 常用命令速查

| 命令 | 大白话 | 什么时候用 |
|------|--------|-----------|
| `git init` | 让 Git 开始管这个文件夹 | 新建项目时，只用一次 |
| `git add 文件名` | 把文件放进"待提交"区 | 改完代码后 |
| `git commit -m "说明"` | 拍照存档，附上说明 | add 之后 |
| `git push` | 把存档上传到 GitHub | commit 之后 |
| `git pull` | 从 GitHub 下载最新版 | 想拿到远程最新代码时 |
| `git status` | 看看现在啥状态 | 任何时候，确认当前情况 |
| `git log` | 查看历史存档记录 | 想回顾改了啥时 |

## 术语速查

| 术语 | 大白话 |
|------|--------|
| 仓库 (repository) | Git 管理的项目文件夹 |
| commit | 一次存档（快照） |
| 分支 (branch) | 平行世界，互不影响 |
| push | 上传到 GitHub |
| pull | 从 GitHub 下载最新版 |
| PR (Pull Request) | 请求别人合并你的代码 |

## 需要记住的文件

- `.git/` — Git 自动生成的文件夹，存版本历史（**别手动碰它**）
- `.gitignore` — 告诉 Git 哪些文件不用管（比如 `venv/`）

## 实操记录

### git init — 让 Git 开始管理项目

**命令：** `git init`

**发生了什么：**
- 在项目根目录创建了 `.git/` 隐藏文件夹
- 这个文件夹里存着所有的版本历史
- 之后所有的 git 命令都是基于这个仓库工作

**验证方式：** `ls -la` 能看到 `.git/` 目录，里面包含 `HEAD`、`config`、`objects` 等子文件

**注意：** 一个项目只需要执行一次 `git init`。做完这一步，Git 开始"盯"着这个项目的所有文件变化。
